2. Core principle: local processing

BrickBuilder is a 3D building application for brick models. No user account is required. The PWA and Android app process projects and imported files locally on your device. They do not automatically send your models or parts lists to me or synchronize them to the cloud.

BrickBuilder does not include advertising or general usage-tracking SDKs and does not use its own service to automatically submit crash reports. The Android app uses RevenueCat for Premium purchase management, as explained in section 7. It does not access contacts, location, camera, or microphone, and it does not read an advertising ID.

3. Data processed on your device

  • Project data: project names, local project IDs, save times, parts, positions, orientations, colors, and other model information.
  • Imported files: IO, LDR, MPD, JSON, XML, or CSV files that you select and their parsed contents. These may include original archives, file names, parts lists, quantities, and embedded metadata, such as author information.
  • Local work and library data: autosaves, required part geometry, installed part packages, catalog and color mappings, local settings, and technical cache data.
  • Export files: files created when saving or sharing, in the local app cache or at a location you select.

Whether this information contains personal data also depends on what you enter in project names or imported files. Avoid including personal information that is not needed for building.

Data is stored locally, including in browser or Android WebView storage such as IndexedDB, app caches, and app-specific file storage. I cannot access this local content remotely.

4. Purposes and legal bases

Local data is used to display and edit models, import and export files, manage parts lists, reopen projects, and save building progress automatically.

Where personal data is processed to provide app functions you request, the legal basis is Article 6(1)(b) GDPR. Where applicable, technically necessary storage and access on your device is based on section 25(2)(2) TDDDG. No tracking cookies are used.

If you contact me, I process the information you provide to handle your request. The legal basis is Article 6(1)(b) GDPR for service-related requests or Article 6(1)(f) GDPR otherwise, based on my legitimate interest in responding. Statutory retention duties may require processing under Article 6(1)(c) GDPR.

5. Internet connections and external services

PWA: When geometry or license files needed for a requested feature are not stored locally, the PWA automatically requests them over HTTPS from the API on the same origin as the PWA. The standard deployment uses https://brickbuilder.blackfishbox.de/api. There is no setting in the PWA to turn off these requests; already cached files remain available offline.

Android: Downloading additional, missing parts geometry online is available only while Premium is unlocked. It is disabled by default even for Premium users. After Premium is unlocked, you must separately enable “Load missing geometry online” in “Privacy & settings”; only then does the app request missing LDraw files, required subfiles, and license texts from https://brickbuilder.blackfishbox.de/api. You can disable it there again at any time. Without Premium, the app does not make these online geometry requests; locally installed or previously cached parts remain available.

For the standard service, these requests go to me as the operator and to the technical hosting provider Ultahost. The server is located in Frankfurt am Main, Germany. These provider details and the 30-day log-retention period below apply to the standard service. A separately self-hosted installation has its own API operator and logging policy. Requests contain the required LDraw file paths, not your project files, local file names, project names, colors, quantities, or complete parts lists. Requested parts could, with considerable effort not undertaken by the server operator and substantial uncertainty, potentially allow inferences about a model.

These connections technically process your public IP address, request time, requested path including the part identifier, and any technical information supplied by the network stack. The server may log requests and errors, such as response status and transferred data volume. The download feature does not add analytics IDs or advertising IDs. Mobile data charges may apply.

In the PWA, a request is made when missing geometry is needed to provide the feature you chose, such as importing or viewing a part. On Android, online geometry loading requires both an active Premium entitlement and your separate opt-in. The opt-in enables the optional download and associated data transfer (Article 6(1)(a) GDPR); buying Premium alone does not grant that permission. You can disable it in the same dialog at any time for future requests. Requests already sent may still reach the server. Downloaded and verified geometry remains stored locally for offline use. If a needed file is neither cached nor available locally, it cannot be displayed while offline or, on Android, without Premium and enabled online loading.

Where technical server logs are needed for security, troubleshooting, and abuse prevention, they are processed based on Article 6(1)(f) GDPR. The legitimate interest is secure and reliable operation of the download service. Log data is not used for advertising or user profiling. The server's access and error logs are retained for 30 days and then deleted. Withdrawal stops future downloads but does not automatically remove server logs that were lawfully collected before the end of this period.

If you open an external link, for example to a source or license, your browser may connect to that provider. The provider usually receives technical connection data such as your IP address and applies its own privacy policy. Opening a link does not automatically send your models.

6. Import, export, and sharing

When catalog search displays a part whose preview geometry is missing, the PWA loads that geometry automatically, one file at a time, from the API described in section 5 and stores it locally. On Android this requires both Premium and enabled online loading. The selected color is rendered on your device and is not transmitted.

The app processes files that you select through the file picker. You decide which files to provide. A document provider you choose may be a cloud storage service; its own privacy terms apply.

An export is first created locally. In the PWA, your browser handles the download or any file/share action you choose; on Android, the system save or share dialog is used. Another app or service receives access to the export only if you choose it. Depending on the format, an export may contain the model, metadata, and retained original content. Review it before sharing.

BrickBuilder does not itself transfer your projects to a cloud service operated by me. Transfers through an email, messenger, or cloud app you choose are handled by that provider.
